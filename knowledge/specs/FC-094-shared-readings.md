# FC-094 · FC-086 · FC-105 — readings shared between the Statistics tools: the specification

**Catalogue:** FC-094 Capability (measured data), FC-086 Control chart (individuals), FC-105 Analysis (how sure) — each gains the same one action; no new entry · **Knowledge:** `spc.control-charts`, `spc.capability-measured`, `stats.confidence-intervals` (`knowledge/methods/`) · **Asked for:** Rowland, 30–31 October 2026 — *"shared readings yes"*, *"option A"*, *"this tool says X, now link to this tool"*, *"stay on tools and make the statistical world"* · **Status:** agreed (Rowland, 31 October) — built with W1 of `docs/TOOLS-WORLDS.md`

## 1. Purpose
A person who has typed or pasted thirty readings into one Statistics tool should not type them again to ask the next question of them. *Is it capable? — is it steady? — how sure are we of the mean?* are three questions of the same column. Today each tool keeps its own readings, so the same thirty numbers are entered three times. The sentence it lets the lead say to the team: **"these are the same readings — here is what each tool says of them."**

**Scope.** This build covers: one action, **Use these readings in…**, on a Capability study (a measurement or a pack by weight), a Control chart (any chart kind) and an Analysis (*how sure* about a mean, or *which shape fits*), which **starts a new study of another of these three tools with the readings copied** and a note on it saying where they came from (**option A**, Rowland: *no new record*). It does not cover: a worksheet of named columns that tools read live (option B, not built — only if A proves too thin); readings that stay in step after the copy (a copy is a copy, said so); counted or pass-or-fail data, a pair, a table, a relation or a gauge study (their readings are not one column of values — each named under *Failure handling*); the hand-overs by answer (*this tool says X, now go to that tool*, W2, `docs/TOOLS-WORLDS.md`); any new calculation or verdict — every figure on the new study is its own tool's, from its own module.

## 2. Users and scenarios
The lead engineer or quality technician at a desk, sometimes on a phone at the line. (1) Thirty fill weights were pasted into a Capability study; the Ppk is amber; they want to see whether the run was steady — **Chart these readings**. (2) A chart of forty seal temperatures has settled; the lead wants the capability against the 180–200 °C limits — **Check capability**, the chart's limits and unit carried. (3) Thirty pasted readings in an Analysis: *how sure am I of the mean* — now *is it capable?* — **Check capability**, asked for its limits.

## 3. Method selection
There is no new statistics here, so no method to choose: the action moves values, and each tool does what it already does with them. What must be chosen is **what travels** and **what is asked again**. Alternatives considered: (B) a worksheet record read by every tool — a new noun, a migration, sync and access to design (`CLAUDE.md`: a fifth concept is almost always the wrong answer) for a benefit option A gives in one tap; a live link (a copy that follows its source) — it would change a study's figures under the person who signed it, and a closed study is a receipt whose figures are frozen. Not chosen for either.

**Established · assumed · chosen.** *Established:* a control chart's limits, a capability index and an interval of the mean each need individual numeric readings in order, and each tool's own checks (steady, bell-shaped, read finely enough) say whether they suit the data (`spc.capability-measured`, `spc.control-charts`) — so copying values between them cannot make a method valid or invalid, and the new study says its own checks. *Assumed:* the readings in the source are the readings the person means (struck ones are not — a struck reading is a mistake kept for the record and travels nowhere); order is time order (the `at` of each reading is kept, so a chart's order is the source's). *Chosen (Faultline's, Rowland 31 October):* a copy, not a link; **the copy is a new study of the target tool on the same line, project, machine and product** — never the same study turned into another; a program's criterion study (`programId`) is **not** inherited, since the copy is not a proof of that test; what is agreed is carried only where the source knows it (unit, limits, nominal) and otherwise **asked by the target** — a capability study needs a limit and is never given an invented one; the source is named on the copy and the copy's readings are its own from then on.

## 4. Inputs
Nothing new is typed to copy. The action offers the target tools other than the study's own, each with one line of what it will do and, where something will be asked first, says so (*"You will be asked for the limits"*). One box: the new study's name, prefilled `"<source name> — chart"`, `"— capability"`, `"— how sure"`; blank refused. What is read from the source: its readings (`value`, `at`, `who`, `note` — not struck, not `arm`ed, not another kind's), its name, unit, limits, nominal, and its line, project, machine, assetId and product. Agreed-before-measured fields are untouched: the target's set-up is the target's (see §3).

## 5. Data suitability
The action is offered only when the source has at least **two** readings that are numbers. Fewer says *"Nothing to share yet — add readings first."* (the item is shown, disabled, with that reason, never hidden — the person should learn it exists). A chart with a short run or a capability study with fewer than its wanted count copies what there is; the new tool says its own *too few* (`MEAN_FROM`, the chart's 20 for limits, capability's count). Readings that are counted (rejects, faults, rates, pass or fail), paired, tabular, a relation's rows or a gauge's parts are **not offered** — the item says *"These readings are counts / pairs / a table — they do not make a single column of values."* so the person is never handed a nonsense chart.

## 6. Calculations
None new. The copy is a pure function (`src/lib/sharedReadings.ts`): the values it takes, the new readings (fresh ids, same value and `at`, `note` kept, `who` kept), the target's agreed record where the source knows it, and the origin note `facts.copiedFrom = { id, tool, name, n, at }`. Independent cases (unit tests, hand-made): (a) 30 readings with 2 struck → 28 copied, none struck, order kept; (b) a capability study with limits 395–405 g, unit g, nominal 400 → a chart agreed with name, unit g, target 400, lower 395, upper 405; (c) a chart with unit °C, no limits → a capability study with **no** `agreed` (set-up asks), readings present; (d) a pack by weight (nominal 400, T1) → a chart with the nominal as target and no limits (the packers' rules are not a spec limit pair); (e) an analysis *share* → not offered; (f) one reading → disabled with its reason; (g) `programId` never copied; (h) new ids differ from the source's and from each other.

## 7. Outputs
**On screen:** More ▾ → **Use these readings in…** → a sheet *"Start from these readings"* listing the other two tools, each *Chart these readings · Check capability · How sure am I* with its one line; Start → the new study opens. On the new study, under *Where it sits*, one quiet line: **"Readings copied from *Fill weight — capability*, 30 on 12 Oct · Open"**; if the source has since gained readings, *"The source now has 38 — this copy has 30."* — said, never acted on.

**The report.** Each of the three tools' papers (`studiesPdf`: `studyBlocks`, the chart's and the analysis' blocks) carries, in its context band, **one line** — *Readings copied from "<source>", n readings, <date>.* — when the study has `copiedFrom`, so the paper says where its data came from; no other change to any paper. Studies with no `copiedFrom` print exactly as before (paper parity). No figure, picture or verdict is added; nothing is made up.

## 8. Manufacturing usability
Two taps from a study to a started study on the other tool (More ▾, then the tool), one box that can be left as named. Phone: the item is in the same More ▾; the sheet is the house sheet with the 44 px rows and a way out. No new screen. The new study opens ready to read if limits came across, or at its own set-up if not.

## 9. Failure handling
Fewer than two numeric readings: the item is disabled with its reason. Counted, paired, tabular or gauge data: not offered, with its reason. A closed study (a receipt): its readings can still be shared — the copy is a new open study, the receipt untouched. A client (read-only): the item is not shown (a client cannot start a study); a team member on a project may. The source deleted later: the copy stands, the origin line says *"copied from a study that has since been deleted"*. Offline: the copy is made on the device and syncs as any study does. A blank name refused. A study of the target already named the same on the line: allowed (a name is not a key) — the new name carries the target's word so the list tells them apart.

## 10. Integration
**Record:** a new `ToolStudy` through `putStudy` — no new table, no migration (`facts` is JSON; an unknown key survives older builds — `factsOf` keeps it); `facts.copiedFrom` added to `StudyFacts` as a typed optional. The schema test compares columns only and is unaffected. **Where it shows (rule 5):** the source's More ▾ (all three, one mechanism in `ui/StudyActs` StudyBand, so a fourth tool joins by one line), the new study's origin line (`ui/StudyPlace` beside *Where it sits*), its list row carrying the tool's own row as ever, its paper's context line, the line's Tools page and report (it is an ordinary study, so the line report includes it), the world's home *Not used yet → Used*. **Access:** `can.edit` on the project (or no project) to start one; a client is not offered it. **PAGES.md:** the three tools' *More ▾* lines and the origin line; the inventory names the action on a seeded capability study. **No AI. No sensor.**

## 11. Verification
Unit tests of the pure function against the cases in §6 (`src/lib/__tests__/sharedReadings.test.ts`); the acceptance script `scripts/acceptance/shared-readings.mjs`, which seeds a capability study with thirty readings (two struck), copies them into a chart and into an analysis in the browser, reads every figure of the copies against the target tools' own modules (`lib/ie/charts`, `lib/sample`, `tools/analysis/analysis`), copies a chart into a capability study (limits carried, the unit, `agreed` empty where unknown), checks the origin line and the paper's context line read back from the downloaded PDF, a share/count source refusing with its reason, the phone; paper parity against live for every existing paper (unchanged). Gate line added to `CLAUDE.md`.

**Acceptance criteria.**
1. A capability study of measured readings, a chart and an analysis *how sure about a mean* each offer **Use these readings in…** with the other two tools — step 1 of `shared-readings.mjs`.
2. Copying 30 readings (2 struck) makes a new study of the target tool with 28 readings, none struck, in the source's order, new ids — `sharedReadings.test.ts` (a, h) and step 2.
3. Limits, unit and nominal are carried only where the source knows them; where it does not the target's set-up asks — `sharedReadings.test.ts` (b, c, d) and steps 3–4; no limit is ever invented.
4. A program criterion is never inherited (`programId` absent) — test (g).
5. Counts, pairs, tables, relations and gauges are not offered, with their reason; fewer than two values disables, with its reason — test (e, f) and step 5.
6. The new study's figures are the target tool's own (same module, same readings → same tiles and sentence) — step 2 against the modules.
7. The origin is said on the new study and on its paper's context line, and a changed source is said (not acted on) — steps 6–7 (PDF read back).
8. The copy is a new open study on the same line/project/machine/product; the source is untouched (readings, figures, receipt) — step 2.
9. A client is not offered it (the same `canEdit` that withholds Rename — read in `ui/StudyActs`; **not driven in a browser**, listed under *Not yet proved*); the phone works, nothing off the side — step 8.
10. Every existing paper is unchanged — `paper-parity` against live.
Not yet proved: a client not being offered the action, driven in a browser; option B (a worksheet) — not built and not needed until a person asks for columns.

## 12. Maintainability
Code: `src/lib/sharedReadings.ts` (pure), one action in `ui/StudyActs` StudyBand reading it, one sheet component, the origin line in `ui/StudyPlace`. A fourth tool that holds one column of values (a learning curve's runs, a reliability study's intervals) joins by adding itself to the table in that one file with its target prefill; nothing else changes. Left for later, each by its catalogue number: the hand-overs by answer (W2 — the same sheet offered from a verdict, *not steady → Chart it*), a copy that can be refreshed (*Copy the new ones*, only if asked), and option B (FC-105 related) if the readings ever need to be edited as a sheet by several tools at once.

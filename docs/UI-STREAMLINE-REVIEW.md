# Faultline workflow review — 17 November

Personal consultancy use comes first. Simplifying a screen must preserve the technical records, calculations, evidence and reports behind it. The approved Pop identity remains in use.

## Changes following the live review

| Journey | Friction found | Result |
| --- | --- | --- |
| Factory → attention | A card named the issue without its actual place | Where and Owner are explicit and wrap; one press opens the item. Unknown or multi-line locations are stated honestly. Attention precedes the line list. |
| Factory → setup | Repeated setup buttons and an edit door on every line | One Set up destination; edit names and floor positions directly. Client/site/area/type remain optional details. A quiet Open line link retains direct navigation alongside editing. |
| Line → settings | A setup tab led to another dialog, then another disclosure | Settings shows line details, costs and shifts directly. Stop reasons, access and advanced administration remain secondary. |
| Line → machines | Ordering required a setup sheet; Settings showed another, incomplete list | Machines has the full list, including project machines, with direct position controls. Rename stays in More and preserves existing linked evidence. The duplicate Settings list is removed. |
| Line → problems/actions | Saved results pushed urgent work far down the phone page; actions started closed | Problems and visible actions come before saved results. Multi-line project actions remain in an explicitly named section. |
| Machine → problem | Opening a problem took the user into the global register | The existing problem panel opens over the line. Close returns to the same place; the full record remains available. |
| Machine → picture | Empty upload prompts and multiple photo controls repeated on every row | Existing thumbnails remain; the machine page owns upload/change/remove/Undo. Reports keep their pictures. |
| Tools → use | The main tool choice opened its introduction before its working screen | The name opens the working tool; About is secondary. This applies to the library and tool worlds. |
| Problems → location | A retained photo label could override an explicitly selected physical machine | One resolver prioritises the selected machine in cards, panels, action trackers, Luna reads and report rows. Original photo/source labels remain evidence. Cost inputs use the same physical machine; formulas are unchanged. |
| Tablet → navigation | Full-width search squeezed out the current place | Search becomes a named icon on tablet; the current place keeps space. Desktop retains full search. |

## Applying the design lesson across screens

The line header no longer repeats its Programs tab. Tool-world pages put usable tools and questions first; the complete method catalogue, counts and status move into Methods and coverage. Their single-item More → All tools menu is removed: shared Tools navigation returns in one press. These changes reduce competing choices while retaining every catalogue entry and program workflow.

## Workspace boundaries retained

Tools owns the library and saved uses; Testing owns criteria, trials and evidence; Projects owns organised improvement work; Factory owns physical areas/lines/machines; Luna owns conversations and optional assistance. Opening a linked record preserves its ownership and context. A project is not required for standalone tools or testing. Reports are read from the existing records rather than introducing another entry form.

The preceding Pop/workspace release was verified across the full app. This follow-up expands the shared navigation, setup and location changes through those workspaces. Its full release verification covers all page contracts, acceptance stories, journeys, report comparisons/fuzz cases and two-device sync before publication; this document is not a claim that a pending gate has passed.

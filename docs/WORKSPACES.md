# Clear workspaces — 17 November 2026

Rowland asked whether connecting every tool, test, project and Luna had made the app too difficult to operate, and authorised corrective action. This supersedes the 16 November rule that hides the global Tools door and the earlier fullscreen assistant shell.

The records stay linked where those links carry evidence or ownership. The interface gives each job a clear home:

| Home | Job |
| --- | --- |
| Tools | Choose a tool or reopen any saved use; no project required. |
| Testing | Plan and run verification, with criteria, evidence and results; no project required. |
| Projects | Organise selected work through an improvement method. |
| Factory | Organise lines, machines and their work, with place reports. |
| Luna | Optional help; the normal app navigation remains available. |

Tools has Library and Saved work views. Saved work is searchable, keeps each use distinct and respects the active client. Opening it from Tools stays in that workspace even when the record belongs to a project or line. Following an explicit line/project link leaves the workspace. Opening a record from the existing line or project flow keeps that flow. A URL presentation marker carries the workspace; it changes no saved record, permission or calculation.

Testing reuses the existing line-program verification flow, with active-client filtering. It does not merge check-log observations with formal planned trials. Projects remain optional for those programs. The phone bar gives direct access to Factory, Tools and Projects, with quick problem capture and More; Testing, Today and Luna remain in the menu.

PDF content and its record links remain unchanged. A tool's own report stays with its record; place/project reports combine their explicitly associated work. No links are deleted and no records are copied merely to change navigation.

Acceptance: from Luna reach Tools and Projects directly; from Tools reopen a project-linked saved use without being moved into project navigation; its line/project links still open explicitly; tool view/list changes retain Tools; new standalone work has no project; Testing opens and runs a line's verification with no project and does not mix clients; phone/tablet/desktop navigation remains usable. These are proved by the workspace-separation acceptance and existing tool/testing/client/report stories.
